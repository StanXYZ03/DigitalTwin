# M0/M11 数字孪生、环境监测与模式切换前后端开发说明

## 1. 文档目的

本文目标是在已经稳定运行的 M0 计数器数字孪生基础上，增加以下能力：

1. 展示 SHT40 温湿度、核心板电流和底板电流；
2. 在网页上一键选择 M0 计数器或 M11 点阵实验；
3. 根据遥测中的 `mode` 自动切换前端页面；
4. 正确解析 M11 的 `PO` 状态字，并显示 16×16 点阵数字孪生；

## 2. 主实验遥测


主实验遥测约每 100 ms 一包；环境模块约每 1 s 上报一轮。环境数据和主实验遥测使用各自的序列号，不能假设四个环境模块与某个主遥测包严格同时产生。STM32 上传的主遥测示例：

```json
{
  "type": "telemetry",
  "experiment": "exp2-01_hex_counter_32",
  "source": "fmc16",
  "sequence": 13520,
  "timestamp_ms": 602341,
  "mode": 0,
  "clk_sel": 23,
  "clock_hz": 12500000,
  "pi_applied": 0,
  "pi_requested": 0,
  "pi_virtual_toggle": 0,
  "virtual_key_state": 0,
  "virtual_key_count": 8,
  "control_ack": 123456,
  "panel_control_ack": 223456,
  "key_state": 0,
  "key_event_count": 15,
  "po": 106,
  "pio": 1024
}
```

公共字段：

| 字段 | 含义 |
| --- | --- |
| `source` | 固定为 `fmc16` |
| `sequence` | 主快照 32 位序号，按无符号回绕规则比较新旧 |
| `timestamp_ms` | STM32 启动后的毫秒数 |
| `mode` | `0` 表示 M0，`11` 表示 M11 |
| `experiment` | M0 为 `exp2-01_hex_counter_32`；M11 为 `exp3-04_dot_matrix_led` |
| `po` | Xilinx `PO[31:0]` 的无符号值 |
| `pio` | Xilinx `PIO[15:0]` 的采样值 |
| `control_ack` | 最近成功执行的按键控制命令 ID |
| `panel_control_ack` | 最近成功执行的拨码、蜂鸣器或模式命令 ID |

后端同时校验 `source`、`mode`、序列号和源 IP。设备超过 500 ms 无新主遥测标为 `stale`，超过 3 s 标为 `offline`。不能继续用最后一帧伪装在线。

## 3. 三个传感器

### 3.1 模块名称与页面名称

使用以下对应关系：

| UDP `module` | 页面名称 | 特征 |
| --- | --- | --- |
| `sht40` | 环境温湿度 | 温度与相对湿度 |
| `ina226_u10` | 核心板电流 | 电流较小 |
| `ina226_u44` | 底板电流 | 电流较大 |


### 3.2 SHT40 数据

```json
{
  "ver": "1.0",
  "type": "module.data",
  "module": "sht40",
  "seq": 3001,
  "ts_ms": 602000,
  "data": {
    "temp_dezi": 253,
    "rh_dezi": 487,
    "temp_ok": 1,
    "hi_alarm": 0,
    "level": 0,
    "last_result": 0,
    "fail_streak": 0,
    "raw_temp": 27654,
    "raw_rh": 31246,
    "probe_mask_40_47": 19,
    "probe_mask_known": 63,
    "pca9617_enabled": 1
  }
}
```

- 页面温度：`temp_dezi / 10`，单位 `°C`；该值允许负数。
- 页面湿度：`rh_dezi / 10`，单位 `%RH`。
- `temp_ok=0` 时必须显示“传感器无效”，不能显示缓存值为正常值。
- 温度等级：`0=正常`、`1=预警`、`2=告警`、`3=紧急`。
- 当前阈值为 58 °C、60 °C、65 °C；

### 3.3 INA226 数据

两路 INA226 使用相同结构：

```json
{
  "ver": "1.0",
  "type": "module.data",
  "module": "ina226_u44",
  "seq": 3003,
  "ts_ms": 602000,
  "data": {
    "cur_ma": 132,
    "over_cur": 0,
    "valid": 1,
    "level": 0,
    "last_result": 0,
    "fail_streak": 0,
    "raw_shunt": 1056,
    "configured": 1
  }
}
```

- `cur_ma` 是有符号整数，单位 mA。
- `valid=0` 时页面显示 `--` 和“传感器无效”。
- `over_cur=1` 等价于 `level >= 2`。
- `level` 颜色建议：0 绿色、1 黄色、2 橙红、3 红色闪烁。
- 核心板电流 `ina226_u10` 当前约 29.75/35/52.5 mA 对应预警/告警/紧急。
- 底板电流 `ina226_u44` 当前为 340/400/600 mA 对应预警/告警/紧急。
- 连续三次采样失败后 STM32 才会清除有效位，前端仍应以收到的 `valid` 为准。

### 3.4 后端整合规则

`module.data` 按模块名独立保存：

```js
snapshot.modules = {
  sht40:       { ...packet, receivedAtMs, ageMs, online },
  ina226_u10:  { ...packet, receivedAtMs, ageMs, online },
  ina226_u44:  { ...packet, receivedAtMs, ageMs, online },
  pcal6524:    { ...packet, receivedAtMs, ageMs, online }
};
```

每个模块独立检查 `seq`、重复包、乱序包和 3 s 超时。STM32 重启时主遥测序号和时间戳回退，后端应增加 `deviceEpoch` 并清空旧模块缓存，避免把上一次运行的传感器值拼到新会话。

## 4. 模式切换

### 4.1 后端到 STM32 的 M0PC 帧

模式命令仍使用 16 字节可靠控制帧：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | ASCII `M0PC` |
| 4 | 1 | 版本 `1` |
| 5 | 1 | target=`3`，表示 mode |
| 6 | 1 | 模式编号 `0` 或 `11` |
| 7 | 1 | 保留，必须为 `0` |
| 8 | 4 | 大端 `commandId`，不能为 0 |
| 12 | 2 | 保留，必须为 0 |
| 14 | 2 | 前 14 字节的 CRC16-CCITT，大端 |

后端每 250 ms 重发一次，最多 8 次。同一时间只允许一个面板命令在途，后续命令进入队列。STM32 通过主遥测的 `panel_control_ack` 回传最后成功执行的 `commandId`。

### 4.2 硬件端完整切换顺序

正式双模式固件应按以下顺序执行，前后端不要绕过 STM32直接控制拨码：

1. PCAL6524 先关闭所有 BSW 路由，执行 break-before-make；
2. STM32 通过 FMC opcode `0x0004 SET_MODE` 请求 Lattice 切换到 0 或 11；
3. 等待事务 ID 匹配、CRC 正确的 RESPONSE；
4. M0 保持 BSW 全断开；M11 应用点阵路由位图 `0x01B3` 并使能复用器；
5. 更新 `panel_control_ack`；
6. 后续 FMC 快照中的 `mode` 必须与目标一致。


## 5. M11 遥测解析

### 5.1  M11 PO

正式点阵程序的 `PO[31:0]` 定义如下：

| 位 | 字段 | 含义 |
| --- | --- | --- |
| 31:24 | `experimentId` | 固定 `0xD4` |
| 23 | `running` | 点阵动画运行状态 |
| 22 | `direction` | 动画方向 |
| 21:20 | `patternMode` | 0～3 四种图案 |
| 19:18 | 保留 | 应为 0 |
| 17:16 | `speed` | 0～3 四档速度 |
| 15:8 | `framePos` | 动画逻辑帧位置 |
| 7:4 | `scanHeartbeat` | 扫描活动心跳低四位 |
| 3:0 | `scanRow` | 当前扫描行/列索引，仅用于诊断 |

后端解析函数示例：

```js
function decodeM11(po) {
  const word = po >>> 0;
  return {
    valid: (word >>> 24) === 0xD4,
    experimentId: word >>> 24,
    running: Boolean((word >>> 23) & 1),
    direction: (word >>> 22) & 1,
    patternMode: (word >>> 20) & 3,
    speed: (word >>> 16) & 3,
    framePos: (word >>> 8) & 0xff,
    scanHeartbeat: (word >>> 4) & 0x0f,
    scanRow: word & 0x0f
  };
}
```

### 5.2 点阵状态简报与前端重建

M11 模式下，Xilinx 通过 `PO[31:0]` 输出 5.1 定义的实验逻辑状态，Lattice 将 `PO/PIO` 原样放入 FMC16 状态包，STM32 校验并上传，后端解析状态，前端使用与该实验版本配套的渲染器重建 16×16 理想画面。

数据链路如下：

```text
Xilinx 点阵实验状态
  -> PO[31:0] 状态简报
  -> Lattice FMC16 透明采集
  -> STM32 UDP 遥测
  -> 后端解析 exp3-04-state-v1
  -> 前端 16×16 逻辑画面重建
```



后端向前端提供结构实例：

```json
{
  "encoding": "exp3-04-state-v1",
  "valid": true,
  "experimentId": 212,
  "running": false,
  "direction": 0,
  "patternMode": 0,
  "speed": 0,
  "framePos": 0,
  "scanHeartbeat": 0,
  "scanRow": 0
}
```

字段用途如下：

| 字段 | 前端用途 |
| --- | --- |
| `experimentId` | 选择 `exp3-04` 对应的版本化渲染器，当前必须为 `0xD4` |
| `running` | 显示运行/暂停；暂停时画面保持在当前 `framePos` |
| `patternMode` | 选择四种图案生成规则之一 |
| `framePos` | 当前逻辑动画位置，是画面重建的主要相位输入 |
| `direction` | 显示并重建当前运动方向 |
| `speed` | 显示当前速度档位； |
| `scanHeartbeat` | 判断 Xilinx 点阵扫描逻辑是否仍在工作，仅作健康状态 |
| `scanRow` | 当前瞬时扫描索引，仅作诊断，不直接绘制为一整帧 |

### 6.3 点阵行数据生成器

统一约定 `rows[y]` 的 bit `x` 对应网页坐标 `(x,y)`；`x=0` 为最左列，`y=0` 为最上行。该坐标是前端逻辑坐标，不直接套用实体板的 `I_ROW/I_COL` 引脚重排。

```js
const MATRIX_SIZE = 16;
const MATRIX_MASK = 0xffff;

function emptyMatrixRows() {
  return new Uint16Array(MATRIX_SIZE);
}

function setMatrixPixel(rows, x, y) {
  if (x < 0 || x >= MATRIX_SIZE || y < 0 || y >= MATRIX_SIZE) return;
  rows[y] = (rows[y] | (1 << x)) & MATRIX_MASK;
}

function rotateLeft16(value, shift) {
  const s = shift & 0x0f;
  const word = value & MATRIX_MASK;
  if (s === 0) return word;
  return ((word << s) | (word >>> (16 - s))) & MATRIX_MASK;
}

/*
 * 与当前 exp3-04 RTL 的边界停留规则一致：到达 0 或 15 时先改变
 * 方向，下一逻辑帧再离开边界。初始位置为 1。
 */
function bounceCoordinate(stepCount) {
  let position = 1;
  let reverse = false;
  const count = Number(stepCount) & 0xff;

  for (let i = 0; i < count; i += 1) {
    if (!reverse && position === 15) reverse = true;
    else if (reverse && position === 0) reverse = false;
    else position += reverse ? -1 : 1;
  }
  return position;
}

function renderPatternV1(patternMode, framePos, direction) {
  const rows = emptyMatrixRows();
  const frame = Number(framePos) & 0xff;
  const mode = Number(patternMode) & 0x03;

  if (mode === 0) {
    // Mode 0：walking-1，framePos 高四位为 y，低四位为 x。
    setMatrixPixel(rows, frame & 0x0f, (frame >>> 4) & 0x0f);
    return rows;
  }

  if (mode === 1) {
    // Mode 1：实体点阵方向与网页逻辑坐标相反，前端镜像 X/Y。
    const x = 15 - bounceCoordinate(frame);
    const y = 15 - bounceCoordinate(frame >>> 1);
    setMatrixPixel(rows, x, y);
    return rows;
  }

  if (mode === 2) {
    // Mode 2：矩形边框。当前单色实体点阵中，沿边框运动的追逐点
    // 与边框同色，因此逻辑位图仍表现为完整边框。
    rows[0] = MATRIX_MASK;
    rows[15] = MATRIX_MASK;
    for (let y = 1; y < 15; y += 1) rows[y] = 0x8001;
    return rows;
  }

  // Mode 3：固定字形循环移位，并在第 13 行显示方向指示。
  const glyph = [
    0x0000, 0x0000, 0x3c78, 0x4284,
    0x999a, 0xa5a5, 0xa5a5, 0x999a,
    0x8181, 0x4242, 0x3c3c, 0x0000,
    0x0000, 0x0000, 0x0000, 0x0000
  ];
  for (let y = 0; y < MATRIX_SIZE; y += 1) {
    rows[y] = rotateLeft16(glyph[y], frame & 0x0f);
  }
  rows[13] = direction ? 0x00ff : 0xff00;
  return rows;
}
```

`renderPatternV1()` 必须与 `experimentId=0xD4` 对应的 Xilinx RTL 同版本维护。若学生修改了图案算法但仍输出 `0xD4`，网页只能继续按旧规则重建，结果会与学生的新图案不一致。因此平台正式开放时应冻结参考实验的状态编码；扩展实验需要分配新的 `experimentId` 或新的 `encoding` 版本。

const matrixPixels = [];

function drawMatrixRows(rows) {
  for (let y = 0; y < MATRIX_SIZE; y += 1) {
    const row = Number(rows[y]) & MATRIX_MASK;
    for (let x = 0; x < MATRIX_SIZE; x += 1) {
      const index = y * MATRIX_SIZE + x;
      matrixPixels[index].classList.toggle('on', Boolean(row & (1 << x)));
    }
  }
}

### 6.5 遥测驱动更新

后端可以直接输出 `snapshot.matrix`，也可以只输出 `snapshot.po`，由前端调用 5.1 的 `decodeM11()`。推荐后端统一输出 `matrix`，避免多个客户端重复实现位域解析。

```js
const patternNames = ['walking-1', '弹跳点', '边框', '图形滚动'];
const speedNames = ['4 fps', '8 fps', '20 fps', '40 fps'];
let lastMatrixServerSeq = -1;

function matrixStateFromSnapshot(snapshot) {
  if (!snapshot || snapshot.mode !== 11) return null;
  if (snapshot.matrix) return snapshot.matrix;
  return {
    encoding: 'exp3-04-state-v1',
    ...decodeM11(snapshot.po)
  };
}

function renderMatrixSnapshot(snapshot) {
  const state = matrixStateFromSnapshot(snapshot);
  const inM11 = snapshot && snapshot.mode === 11;
  matrixPanel.hidden = !inM11;
  if (!inM11) return;

  // 丢弃倒序或重复的服务端快照，避免旧 UDP 包造成画面回跳。
  if (Number.isInteger(snapshot.serverSeq) &&
      snapshot.serverSeq <= lastMatrixServerSeq) return;
  if (Number.isInteger(snapshot.serverSeq)) {
    lastMatrixServerSeq = snapshot.serverSeq;
  }

  const valid = Boolean(state && state.valid &&
                        state.encoding === 'exp3-04-state-v1' &&
                        state.experimentId === 0xd4);
  matrixPanel.classList.toggle('invalid', !valid);
  matrixPanel.classList.toggle('stale', snapshot.freshness === 'stale');

  if (!valid) {
    document.getElementById('matrixHealth').textContent = '状态简报无效';
    return; // 保留最后一幅有效画面，不清屏、不本地补帧。
  }

  const rows = renderPatternV1(
    state.patternMode,
    state.framePos,
    state.direction
  );
  drawMatrixRows(rows);

  const health = snapshot.freshness === 'fresh'
    ? `在线 · scan ${state.scanHeartbeat.toString(16).toUpperCase()}`
    : '遥测延迟';
  document.getElementById('matrixHealth').textContent = health;
  document.getElementById('matrixRun').textContent =
    `运行：${state.running ? '运行' : '暂停'}`;
  document.getElementById('matrixPattern').textContent =
    `图案：${patternNames[state.patternMode] ?? '未知'}`;
  document.getElementById('matrixSpeed').textContent =
    `速度：${speedNames[state.speed] ?? state.speed}`;
  document.getElementById('matrixDirection').textContent =
    `方向：${state.direction ? '反向' : '正向'}`;
  document.getElementById('matrixFrame').textContent =
    `帧位置：${state.framePos}`;
}
```

把 `renderMatrixSnapshot(snapshot)` 接入现有 WebSocket `message` 处理函数，并与当前页面的主 `render(snapshot)` 使用同一份快照：

```js

```

### 6.6 必须满足的显示规则

1. 只有 `mode==11` 且 `experimentId==0xD4` 时显示点阵组件。
2. 每次画面变化必须由一份新的硬件遥测触发，浏览器不得用 `setInterval()` 自行推动动画。
3. `running=false` 时继续显示 `framePos` 对应画面，不清屏。
4. 快照短暂丢失或无效时保持最后一幅有效画面，并显示“遥测延迟”或“状态简报无效”。
5. `serverSeq` 倒退或重复时不更新点阵，防止旧包覆盖新状态。
6. 切回 M0 后隐藏点阵组件，恢复计数器数码管和 LED 页面。
