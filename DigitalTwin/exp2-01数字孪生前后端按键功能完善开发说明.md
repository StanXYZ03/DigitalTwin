# exp2-01 数字孪生前后端按键功能完善开发说明

## 1 文档目的

本文是在《exp2-01 数字孪生前后端协作开发说明》所述只读数字孪生基础上，对按键模块进行完整双向扩展的开发约定。实现目标不是只增加五个实验功能按钮，而是把面板上 F1～F10 全部建立为数字孪生对象：

- 实体 F1～F10 的按下和松开状态必须上传网页；
- 网页 F1～F10 必须支持鼠标和触摸屏长按，并把按下、保持、松开同步到设备端；
- 实体来源和网页来源必须同时保留，不能由一方覆盖另一方；
- 当前 exp2-01 只使用 F2～F6，不得因此删除或禁用 F1、F7～F10；
- 平台实现不得要求用户修改 XC7A100T 上原有的实验 HDL。

完整链路如下：

```text
实体 F1..F10 ──> Lattice 消抖、状态采集 ──> FMC16 ──> STM32 ──> UDP 遥测
                                                                    │
                                                                    v
网页 F1..F10 <── WebSocket 完整快照 <── Node.js 数字孪生服务器
      │
      └── pointerdown / pointerup ──> REST ──> UDP M0KC ──> STM32
                                                       │
                                                       └── XOR 合并后驱动 XC7A PI
```

## 2 按键名称、位图和实验功能

### 2.1 名称统一

面板、网页、REST API 和开发文档统一使用丝印名称 `F1`～`F10`，不再把网页按钮命名为 KEY3～KEY7。

旧平台逻辑把部分面板键称为 KEY3～KEY7，因此曾出现“面板 F2 对应软件 KEY3”的现象。新接口以物理丝印为唯一对外名称，旧逻辑名只作为兼容说明。

### 2.2 十键位图

`key_state` 和 `virtual_key_state` 都使用低 10 位：

| 位 | 面板/网页名称 | Lattice 引脚 |
| ---: | --- | ---: |
| bit0 | F1 | 9 |
| bit1 | F2 | 10 |
| bit2 | F3 | 11 |
| bit3 | F4 | 12 |
| bit4 | F5 | 13 |
| bit5 | F6 | 14 |
| bit6 | F7 | 15 |
| bit7 | F8 | 19 |
| bit8 | F9 | 20 |
| bit9 | F10 | 21 |

位值为 `1` 表示对应来源当前处于按下状态，位值为 `0` 表示松开。高 6 位必须为 0。

### 2.3 exp2-01 功能映射

| 网页/面板键 | XC7A PI | exp2-01 功能 | 当前实验是否使用 |
| --- | ---: | --- | --- |
| F1 | — | 保留 | 否 |
| F2 | `PI[8]` | 暂停/继续计数 | 是 |
| F3 | `PI[9]` | 计数值清零 | 是 |
| F4 | `PI[10]` | 切换为递减计数 | 是 |
| F5 | `PI[11]` | 切换为递增计数 | 是 |
| F6 | `PI[12]` | 切换 LED 移动方向 | 是 |
| F7 | — | 保留 | 否 |
| F8 | — | 保留 | 否 |
| F9 | — | 保留 | 否 |
| F10 | — | 保留 | 否 |

“当前实验未使用”只表示 exp2-01 不消费该键，不表示该键不存在。F1、F7～F10 仍必须完成实体采集、网页长按、松开、可靠下发、命令确认和状态显示。

## 3 按键状态与 XOR 仲裁

### 3.1 两类状态不可混用

- `key_state`：Lattice 采集的实体 F1～F10 当前电平状态；
- `virtual_key_state`：STM32 保存的网页 F1～F10 当前保持状态；
- `pi_requested`：实体 F2～F6 的有效按下沿累计形成的实验翻转值；
- `pi_virtual_toggle`：网页 F2～F6 的有效 down 沿累计形成的实验翻转值；
- `pi_applied`：STM32 最终写入 PI 扩展器的值。

当前用户确认采用 XOR 仲裁：

```text
pi_applied = pi_requested XOR pi_virtual_toggle
```

网页需要展示合并状态时，同样可计算：

```text
effective_key_state = key_state XOR virtual_key_state
```

但前端不得只保存合并结果，必须保留 `physicalKeys` 和 `virtualKeys`，否则无法判断动作来自实体还是网页。

### 3.2 长按语义

网页不能再使用 `click` 作为唯一输入事件：

1. `pointerdown` 时发送一次 `down`；
2. 按住期间不重复发送命令，`virtual_key_state` 对应位持续为 1；
3. `pointerup` 时发送一次 `up`，对应位恢复为 0；
4. `pointercancel`、`lostpointercapture` 和窗口失焦也必须补发 `up`，防止卡键；
5. F2～F6 只在新的 down 沿翻转一次 PI，up 不产生第二次实验事件；
6. F1、F7～F10 的 down/up 同样发送和确认，但 exp2-01 不修改 PI。

这种处理与实体按键路径一致：长按期间状态一直保持，实验功能只在消抖后的按下沿触发一次。

### 3.3 同一按键同时操作

实体键和网页键没有优先级，二者均作为独立输入事件处理。例如实体 F2 按住时再在网页按下 F2：

- 实体状态和网页状态都会分别显示为按下；
- 两次有效按下沿都会分别翻转各自的累计量；
- 最终 PI 按 XOR 计算，两个翻转可能互相抵消；
- 任一来源松开只改变该来源的保持状态，不产生新的 PI 翻转。

这是当前确定的 XOR 产品语义，前后端不得私自改成覆盖、优先级或 OR 仲裁。

## 4 STM32 遥测格式

STM32 继续通过 UDP 5005 上报完整 JSON 快照。当前按键完善后的典型报文为：

```json
{
  "type": "telemetry",
  "experiment": "exp2-01_hex_counter_32",
  "source": "fmc16",
  "sequence": 2847,
  "timestamp_ms": 894072,
  "mode": 0,
  "clk_sel": 23,
  "clock_hz": 12500000,
  "pi_applied": 256,
  "pi_requested": 0,
  "pi_virtual_toggle": 256,
  "virtual_key_state": 2,
  "virtual_key_count": 1,
  "control_ack": 305419896,
  "key_state": 0,
  "key_event_count": 8,
  "po": 305441741,
  "pio": 1
}
```

新增或需要重点处理的字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `key_state` | uint16 | 实体 F1～F10 当前状态位图 |
| `key_event_count` | uint16 | Lattice 接受的实体按下事件累计数，允许回绕 |
| `virtual_key_state` | uint16 | 网页 F1～F10 当前保持状态位图 |
| `virtual_key_count` | uint16 | STM32 接受的网页功能按下事件累计数，允许回绕 |
| `pi_requested` | uint16 | 实体按键路径形成的 PI 请求值 |
| `pi_virtual_toggle` | uint16 | 网页按键路径形成的 PI 翻转掩码 |
| `pi_applied` | uint16 | 实际写入 XC7A PI 扩展器的合并值 |
| `control_ack` | uint32 | STM32 最后接受的 down/up 命令 ID |

后端必须校验上述位图均在 uint16 范围内。F1～F10 的有效状态位只允许低 10 位，但为兼容调试字段，接收层可保留原始 uint16，渲染层只展开低 10 位。

## 5 后端控制协议

### 5.1 REST API

所有十个按键使用同一接口：

```http
POST /api/digital-twin/devices/{deviceId}/keys/F{1..10}/{down|up}
```

示例：

```http
POST /api/digital-twin/devices/board-001/keys/F2/down
POST /api/digital-twin/devices/board-001/keys/F2/up
```

成功排队返回 HTTP 202：

```json
{
  "status": "queued",
  "commandId": 305419896,
  "key": "F2",
  "action": "down"
}
```

状态码约定：

| 状态码 | 含义 |
| ---: | --- |
| 202 | 命令已排队，尚不等于 STM32 已执行 |
| 400 | F 编号或 action 非法 |
| 429 | 控制队列已满 |
| 503 | 设备离线，无法可靠下发 |

不要继续调用旧的 `/keys/3/press`～`/keys/7/press` 接口。

### 5.2 UDP M0KC 控制帧

Node.js 后端向 STM32 返回固定 16 字节二进制帧，多字节字段为大端：

| 偏移 | 长度 | 字段 | 规则 |
| ---: | ---: | --- | --- |
| 0 | 4 | magic | ASCII `M0KC` |
| 4 | 1 | version | `1` |
| 5 | 1 | key | F 编号，范围 1～10 |
| 6 | 1 | action | `1=down`，`2=up` |
| 7 | 1 | reserved | `0` |
| 8 | 4 | command_id | 非零 uint32 |
| 12 | 2 | reserved2 | `0` |
| 14 | 2 | crc16 | 对字节 0～13 计算 CRC-16/CCITT-FALSE |

CRC 参数：初值 `0xFFFF`，多项式 `0x1021`，不反射，无最终异或。

STM32 必须检查数据报长度、服务器 IP/端口、magic、版本、按键范围、action、保留字段、CRC 和命令序号。相同 `command_id` 的重发只能再次确认，不能重复执行。

### 5.3 可靠队列与确认

后端一次只保持一个在途命令：

1. 为每个 down 或 up 分配新的非零 uint32 `commandId`；
2. 立即向最近一次合法遥测的 UDP 源端点发送 M0KC；
3. 250 ms 未在遥测 `control_ack` 中看到相同 ID，则重发；
4. 最多尝试 8 次；
5. 收到确认后发送下一条排队命令；
6. 达到重试上限后标记 `failed`，不得伪造成功状态。

后端收到 HTTP 202 只能显示“已排队”。只有 WebSocket 快照中 `control.status=acknowledged`，才能显示“STM32 已执行”。

## 6 后端提供给前端的快照

Node.js 在原始遥测基础上生成三个十元素布尔数组：

```json
{
  "physicalKeys": [false, true, false, false, false, false, false, false, false, false],
  "virtualKeys":  [false, false, false, false, false, false, false, false, false, false],
  "keys":         [false, true, false, false, false, false, false, false, false, false]
}
```

- `physicalKeys[i]` 来自 `key_state bit i`；
- `virtualKeys[i]` 来自 `virtual_key_state bit i`；
- `keys[i]` 是二者 XOR 后的结果；
- 数组下标 0～9 分别对应 F1～F10。

WebSocket 路径保持为：

```text
ws://服务器:8080/ws/digital-twin/devices/{deviceId}
```

WebSocket 每次推送完整快照。浏览器首次进入和断线重连后先通过 GET snapshot 补齐状态，不能假定所有键初始均为松开。

## 7 前端实现要求

### 7.1 页面布局

Vivado 开发页面左下角“数字孪生”区域必须完整显示：

1. 8 位十六进制数码管；
2. LED0～LED11；
3. 实体 F1～F10 状态；
4. 可操作的网页 F1～F10；
5. 设备在线状态和最近一次控制结果。

F1、F7～F10 可以标注“本实验未使用”，但按钮不得隐藏、删除或禁用。设备离线时才统一禁用控制按钮。

### 7.2 指针事件

推荐实现：

```javascript
button.addEventListener('pointerdown', () => setKey(fNumber, 'down'));
button.addEventListener('pointerup', () => setKey(fNumber, 'up'));
button.addEventListener('pointercancel', () => setKey(fNumber, 'up'));
button.addEventListener('lostpointercapture', () => setKey(fNumber, 'up'));
```

要求：

- 同一次保持期间不得重复发送 down；
- 鼠标、触摸和触控笔统一使用 Pointer Events；
- pointerdown 后调用 `setPointerCapture`，防止指针滑出按钮导致丢失 up；
- 页面失焦时对本地仍处于按下状态的键补发 up；
- up 请求建议设置 `keepalive: true`；
- 不允许用 click 代替 down/up，否则无法表达长按。

### 7.3 显示规则

- 实体键灯仅由 `physicalKeys` 决定；
- 网页可操作按钮在本地按住、实体按住或 `virtualKeys` 为真时显示按下效果；
- 建议通过颜色、边框或提示文字区分实体来源和网页来源；
- 命令 pending 时不要冻结 PO、PIO 或其他按键；
- stale/offline 时保留最后状态，但明确显示数据延迟或离线；
- 页面刷新后不得在未读取快照前擅自发送 up 或清除服务器状态。

## 8 安全与异常恢复

- 浏览器异常关闭可能来不及发送 up。产品化后端应增加会话租约或心跳释放机制；当前局域网版本至少实现 pointercancel、失焦和 keepalive up。
- 网络中断期间禁止接受新的按键操作；恢复后先同步完整快照。
- 后端不得根据按钮动画自行修改硬件状态，硬件状态以 STM32 遥测为准。
- F1、F7～F10 即使不改变 exp2-01 的 PI，也必须等待 STM32 `control_ack`，以证明十键控制链路完整。
- 不得把控制失败解释为一次成功短按，也不得在前端本地补做实验动画。

## 9 联调步骤

1. 确认 STM32 地址为 `192.168.100.50`，服务器地址为 `192.168.100.100`，UDP 端口为 5005，HTTP 端口为 8080。
2. 打开网页并确认状态为在线，PO、PIO 持续更新。
3. 依次按下实体 F1～F10，确认网页对应实体状态在按住期间为真、松开后恢复。
4. 依次长按网页 F1～F10，确认 `virtual_key_state` 相应位在按住期间为 1、松开后为 0。
5. 对每个 down/up 检查 `control.status` 最终进入 acknowledged，且 `control_ack` 等于命令 ID。
6. 验证网页 F2～F6 分别对应暂停/继续、清零、递减、递增、LED 方向；特别检查 F2 必须驱动 PI[8]，不能偏移到 PI[9]。
7. 验证 F1、F7～F10 不改变 exp2-01 计数逻辑，但命令和状态同步正常。
8. 同时操作实体键和网页同名键，确认两路状态独立保存，最终 PI 符合 XOR 公式。
9. 按住网页键后把指针滑出、取消触摸或切换窗口，确认能够自动发送 up，不出现卡键。
10. 断开网络，确认按键被禁用、最后硬件状态保留；恢复网络后重新读取完整快照。

## 10 必须通过的验收用例

| 编号 | 操作 | 预期结果 |
| ---: | --- | --- |
| 01 | 实体 F1～F10 逐个长按 | 网页对应实体状态逐个同步，无编号错位 |
| 02 | 网页 F1～F10 逐个长按 | `virtual_key_state` 对应 bit0～bit9 依次置 1，松开后清零 |
| 03 | 网页 F2 down | 只翻转 `PI[8]`，暂停或继续计数 |
| 04 | 网页 F3 down | 只翻转 `PI[9]`，执行清零功能 |
| 05 | 网页 F4 down | 只翻转 `PI[10]`，切换为递减 |
| 06 | 网页 F5 down | 只翻转 `PI[11]`，切换为递增 |
| 07 | 网页 F6 down | 只翻转 `PI[12]`，切换 LED 方向 |
| 08 | 网页 F1、F7～F10 down/up | 状态和确认完整，exp2-01 的 PI 功能位不变 |
| 09 | 按住网页键 5 秒 | 只产生一次 down，保持状态持续为 1，不自动重复触发 |
| 10 | 松开网页键 | 发送一次 up，保持状态恢复为 0，不产生第二次 PI 翻转 |
| 11 | 同一命令发生 UDP 重传 | STM32 不重复执行，仍返回相同确认结果 |
| 12 | 实体与网页同时操作同一键 | 两路分别记录，最终结果符合 XOR 仲裁 |
| 13 | pointercancel 或窗口失焦 | 自动释放本地保持状态，不出现永久卡键 |
| 14 | 设备离线时操作按钮 | 前端禁止操作或收到 503，不显示伪成功 |
| 15 | 刷新或重连网页 | 首帧完整恢复十键、数码管、LED 和控制状态 |
